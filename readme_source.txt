核心：具备自主认知的分布式AI调度系统，下一代共享算力的微模型基础设施网络。

- 每个任务，自动编译一张简单、可编辑的DAG图；每轮对话，自动演化一张有记忆、可生长的任务树。
- 熟悉的界面，上手0阻力。
- 轻节点“浏览器侧端推理”，中节点“分布式边缘计算”，重节点“云端推理直答”。隐私、成本、速度，不必舍弃任何一个。
- 异构协同：不仅是模型共享，我们致力于建立一张算力点对点共享的 Web 3.0 洋葱网络。
- 杜绝“把大模型当黑盒黑箱调用”的传统做法，建立一套自适应、透明自洽的多智能体协作新范式。


基于意图识别的多轮、有记忆模型仲裁算法：

核心方案：
一、用户指令信封封装。
”上传文件“包含”图片“、”音频”、“文本”（pdf, docx,
pptx, xlsx, csv, txt, json, md）等。

（1）第一层限制：单次最多 5 个文件、总大小不超过 20MB、单文件云端上传不超过 25MB。（硬限制，在客户端与 R2 预签名/上传网关中校验）
（2）第二层限制：图片长宽按最大 2048px 降采样，音频限制时长（超过 10 分钟提示），文本就地提取后总字符量（超出 30000 字符就地截断并提示）。（软限制，视觉上用提示，告知用户”过长可能被裁减“）
客户端在发起任何任务前，均将非结构化的用户输入打包为强类型只读的“统一协议信封“，包含：
{指令载荷（清洗后的自然语言文本提示词）、资产清单、约束上下文}。
其中，约束上下文为客户端请求的响应偏好（响应语言、输出风格）。
资产清单即为：
{提取所有附加文件的 MIME 类型、文件大小与存储寻址指针（此处为R2 Key）、consumed 游标（是否已被某个节点消费？）}。

```typescript
interface UnifiedProtocolEnvelope {
  envelope_id: string;             // 全局唯一信封 UUID
  session_id: string;              // 当前会话 Session ID
  round_index: number;             // 当前会话轮次序号 (从 1 递增)
  instruction_payload: string;     // 清洗后的自然语言文本提示词
  assets_manifest: AssetDescriptor[]; // 关联多模态资产清单
  constraint_context: {            // 客户端请求的环境约束上下文
    target_language: string;       // 偏好输出语言 ('zh' | 'en' | 'auto')
    output_style: string;          // 输出风格 ('concise' | 'detailed' | 'structured')
  };
  metadata: {                      // 运行时元数据
    client_timestamp: number;      // 客户端发起的毫秒时间戳
    char_count_total: number;      // 提示词字符数
    estimated_input_tokens: number;// 预估消耗 Token 量
    has_new_upload: boolean;       // 本轮是否包含新引入资产
    new_upload_modalities: string[];// 本轮新引入资产的模态列表
  };
}

interface AssetDescriptor {
  asset_id: string;                // 资产唯一指纹 ID
  modality: 'image' | 'audio' | 'text_doc' | 'tabular' | 'code' | 'pdf'; // 资产模态
  mime_type: string;               // 原始 MIME 类型
  file_size: number;               // 字节大小
  r2_key: string | null;           // R2 寻址指针（若需云端存储）
  in_memory_text: string | null;   // 就地解构提取出的纯文本 / Markdown
  in_memory_data: string | null;   // Base64 短内联数据（可选）
  consumed: boolean;               // 状态游标：是否已被 DAG 某个上游节点独占消费
  source_digest: string;           // 资产完整性哈希指纹
  is_new: boolean;                 // 是否为本轮对话新上传的资产
  filename: string;                // 文件名
}
```
通过 AWS SigV4 算法在 Worker 签发临时 PUT URL，文件由浏览器直连 R2 存储桶。为了减少用户的上传等待时间、缓解网关计算压力，降采样、裁剪、处理均左移至客户端完成。在浏览器利用 WebAssembly / pdf.js 将 PDF、DOCX、TXT、Markdown 等直接提取为纯文本或 Markdown 表格流（in_memory_text）；图像在客户端利用 HTML5 Canvas API 自动按比例降采样（最大尺寸 2048px，JPEG 0.85 质量压缩），在人眼无损前提下缩减 80%~90% 上传体积；
用户（余额>0）点击提交时（若余额<=0则直接拦截并弹出充值提示），网关提取输入尺寸、上传文件大小及模型最大可能输出长度。
若用户无上传任何附件，网关自动将提示词虚拟为一个文本介质挂载入资产清单，保证 DAG 模态匹配规则一致性。

二、意图特征识别与三步仲裁法
首先引入元数据库。
系统将“真实模型库”与“社区/用户上传模型库”做数据隔离，确保未经沙箱审计的模型不进入调度生产池。
```typescript
interface ModelMetadata {
  model_id: string;                // 唯一标识符
  display_name: string;            // 展示名称
  provider: 'cloudflare' | 'local_webgpu' | 'external_api';
  in_modalities: Modality[];       // 支持输入模态集合
  out_modalities: Modality[];      // 支持输出模态集合
  context_window: number;          // 最大上下文窗口
  cost_per_1k_tokens: number;      // 基础成本权重
  rating: number;                  // 综合质量评分 (1.0 ~ 5.0)
  active_concurrency: number;      // 当前实时活跃并发数
  max_concurrency: number;         // 最大并发上限 (如 300)
  tags: string[];                  // 技能标签集 (e.g. ['multimodal_qa', 'summarize'])
  scene_anchors: string[];         // 专才场景高频锚点列表
  generalist_prior_score: number;  // 通才先验分 (μ0)

```

第一步，安全审计与硬筛选（砍掉低分、满载、窗口不足节点）。
安全审计：
”影子字符串预处理“->”启发式嗅探打标“->"JEV Safety 旁路拦截"
1.”影子字符串预处理“：清洗空格、标点符号、换行符以及零宽字符等，Unicode NFKC 标准化、清洗对抗性空白、标点压平、统一格式，避免用户“绕过“审计
2.”启发式嗅探打标“：如果没命中，直接放行。如果命中，只打标，不熔断，等待第3步"JEV Safety 旁路拦截"决策；如果没有命中，视为安全；
3."JEV Safety 旁路拦截"：仅对第2次被打上标记的内容，用JEV Safety（调用 @cf/cloudflare/clef-flash 专用安全决策侧车）做二元分类即可；(true/false，判定为 true 则立即熔断。)
硬筛选：
读元数据库，筛选掉评分<1分，并发数量>300或达到自身并发上限满载的，未激活的，以及上下文窗口小于当前预估所需Token的模型，尊重用户客户端偏好（若用户勾选“不使用本地模型推理”，则屏蔽 inference_target === 'browser' 的模型），得到候选模型池；
定义“温饱规则”：
{头节点输入模态}<=用户资产中模态<={头节点输入模态}+{尾节点输入模态}
（此处<=代表子集，<代表真子集，+代表并集）
”温饱规则“描述了”所有节点都有资产消费，所有资产都能被至少一个节点消费“的充分必要条件。
通过”温饱规则“，模板池收敛至合法的候选模板池。


第二步，JEV评分与交集运算。对候选模板池，调用 `@cf/cloudflare/clef-flash` 对符合温饱定律的候选模板进行打分，快速评估各模板拓扑对用户提示词的解决匹配度；
模板库中预制边界探测选项；
若 JEV 认定的最高模板得分低于置信度阈值（$\tau_{\text{template}} < 0.35$），或 JEV 直接判定该指令超出当前模板拓扑能力边界：网关触发Fast-Failed机制，装配 `role_unreachable` 单节点，0 消耗算力点数并返回友好的能力边界建议面板，触发Fast-Failed效果。
首选评分第一的模板为征调模板。从征调模板中，提取各个岗位。对每个岗位，查“岗位-标签”表，第一个标签为征调标签，然后利用”胜任定律“：
（1）岗位输入模态<=模型输入模态
（2）岗位输出模态<=模型输出模态
（3）（岗位）征调标签<=模型标签
（此处<=代表子集，<代表真子集，+代表并集）
对候选模型池中，模型元数据库进行“交集运算“，得到”某岗位的精选模型池“。
若”某岗位的精选模型池“=空集，
则再查”岗位-标签“表，对此节点（岗位）所需标签进行降级，即选择下一个标签作为征调标签，重新执行”胜任定律“。若存在降级，需对该节点挂载补偿 Prompt。（即：若某个节点进行过降级，该节点最终的模型需要插入对应”注入提示词“，进一步稳定结果。）若降级到最低后，也没找到模型，报错提示并中止。

第三步，锚点匹配与流量整型。

合格精选模型池内，执行终极精度量化选拔：
1. 向量语义匹配：
   调用 `@cf/baai/bge-m3` 提取用户指令的 Embedding，与各个模型预置的“高频场景锚点”做批量余弦相似度计算，提取最大相似度作为“专才特化相似度”：
   $$\text{sim} = \max_{a \in \text{Anchors}} \cos(\vec{v}_{\text{prompt}}, \vec{v}_a)$$
2. 终极量化打分公式 (Ultimate Scoring Formula)：
   $$S = \mu_0 + \alpha \cdot \max(0, \text{sim} - \tau) + \beta \cdot \frac{R_m}{5.0} - \gamma \cdot \left(\frac{C_{\text{active}}}{C_{\text{max}}}\right)^2$$
   - $\mu_0$ (通才先验分)：通才模型赋予基础分（默认 0.25），专才模型设为 0；
   - $\text{sim} - \tau$ (门控专才加成)：$\tau = 0.65$ 为特化激活阈值，相似度超过阈值方可激活专才斜率爆发加成；
   - $\alpha$ (专才权重系数)：默认设为 0.50；
   - $\beta \cdot \frac{R_m}{5.0}$ (质量基准分)：基于用户与历史评测的评分（$R_m \in [1, 5]$），权重 $\beta = 0.25$；
   - $\gamma \cdot \left(\frac{C_{\text{active}}}{C_{\text{max}}}\right)^2$ (二次方并发惩罚)：当模型负载接近上限时惩罚剧增，自动完成去中心化流量平滑整型，权重 $\gamma = 0.40$。
3. 拓扑实例化输出：
   每个岗位计算得分前 3 名：
   - Top 1：作为主执行模型（Primary Model）；
   - Top 2 & Top 3：作为备选模型池（Standby Models），供前端一键热切换或云端自动故障转移。
最终输出完整拓扑的实例化 DAG 图。

第四步：
信封切片与状态机执行。
“不贪吃”规则·
1. 首节点（In-Degree = 0）：
   - 仅扫描并认领与自身输入模态完全匹配、且 `consumed === false` 的资产；
   - 消费后立即将对应资产的 `consumed` 游标置为 `true`。
2. 中间节点（In-Degree > 0 且 Out-Degree > 0）：
   - 不触碰主信封内的原始多模态物理介质；
   - 严格且仅接收所有直系父节点的产物输出汇总（$\sum \text{Out}_{\text{parent}}$）。
3. 尾节点（Out-Degree = 0）：
   - 接收所有上游产物汇总；
   - 认领剩余所有未被消费的资产（`consumed === false`）；
   - 挂载用户初始 Prompt 与客户端约束上下文（语言、风格），完成最终交付物汇编。

”节点指纹“规则
Hash = SHA256(岗位 + 模型ID + 输入源ID + 注入提示词) 
“节点指纹规则”描述了同一个岗位上的同一个模型，接收到了相同的输入数据与相同的微调注入提示词，其产物在低温度（T≤0.2）下具有确定性

SSE 实时流式事件协议：
Worker 网关与前端之间通过轻量长连接 SSE 进行细粒度可观测事件推送：
- `dag_plan`: 广播被征调模板元信息与 DAG 拓扑节点数组；
- `node_start`: 广播当前开始执行的节点序号、岗位中文/英文名、选中模型及设备目标；
- `client_exec_request`: 当节点为浏览器本地模型时，向前端派发本地推理指令 payload；
- `text_chunk`: 尾节点流式输出时的单个 Token 增量推送（附带 cache_hit 标识）；
- `node_complete`: 单个节点执行完成，回传耗时、Token 统计与输出产物；
- `dag_complete`: 整个 DAG 编排图执行完毕，推送最终综合交付物。

第五步：
多轮对话、动态任务树与 JEV 意图跳变收敛
在交互界面中，用户拥有完全的白盒控制权：
1. 节点模型更换：点击画布任意节点，可在 Top 3 候选模型池中一键切换，前端向网关提交 `{ reRouteMode: 'switch_model', chosenRoleModels: {...} }` 并在原位重新调度；
2. 提示词微调注入：用户可针对特定岗位的执行 Prompt 挂载自定义微调指示（`customRolePrompts`），系统自动重新计算指纹并执行局部刷新；
3. 模板全局重路由：用户可手动切换整体架构模板（`switch_template`），拓扑无缝切换。
4. 用户在右侧聊天框里面，直接开启下一轮对话：此时需要进行JEV 意图跳变收敛。
在多轮交互中，网关不盲目将历史整段对话透传，而是维护一份高度结构化的“会话事实账本”，供 JEV 极速感知上下文：
```markdown
【会话事实账本】：
1. 资产原件介质表:
   - [资产 1]: 模态: image | 文件名: architecture.png | 引入轮次: 第 1 轮
   - [资产 2]: 模态: text_doc | 文件名: api_spec.md | 引入轮次: 第 2 轮
2. 任务树分支目录:
   - 【分支 main: 初始系统分析】
     * 业务领域: 系统架构设计
     * 关联资产: [资产 1 (image)]
     * 产物沉淀: "该架构采用分层解耦..."
     * 状态: 历史活跃分支
   - 【分支 branch_media: 接口规格审计】
     * 业务领域: 接口自动化抽取
     * 关联资产: [资产 2 (text_doc)]
     * 产物沉淀: "定义了 4 个核心 API..."
     * 状态: 当前焦点分支
3. 当前活跃焦点与上下文:
   - 当前正在进行的分支: 【分支 branch_media】
   - 当前分支最新产物基底: "定义了 4 个核心 API..."
[用户最新指令]: {currentPrompt}
```

网关层用一次推理向 JEV 提出结构化判断问题:
依据客观事实账本与信息论充分性，确定用户指令在任务树图拓扑上的依赖边界：

1. 状态 A：ANCHOR_TAIL（尾节点追问 / 形式修饰）
   - 触发特征：指令所属业务领域属于当前活跃任务分支，且指令所需上下文与事实信息完全包含在当前活跃分支的最新产物基底中，无需回溯感知未提取的底层原始介质；
   - 信封重构：逻辑剥离原始大型媒体文件，仅将上一轮最终产物注入为上下文基底，在任务树当前分支末端生长新节点。

2. 状态 B：REBIND_ROOT（回溯原始资产 / 重探上游）
   - 触发特征：指令所属业务领域属于当前活跃任务分支，但指令所需信息在下游抽象中未被包含或已经丢失，仅凭最新产物基底文本无法充分解答，必须穿透回溯至该分支底层的原始多模态物理介质本身进行重新感知；
   - 信封重构：网关重新将该分支原始多模态资产全量挂载回协议信封，将 `consumed` 游标全量复位为 `false`，回到当前分支根节点并装配多模态感知工作流。

3. 状态 C：CROSS_FUSION（跨轮新旧融合对比）
   - 触发特征：本轮有新上传的媒体文件，且用户指令要求将新上传文件与历史既有资产进行联合分析对比；
   - 信封重构：挂载历史所有相关资产 + 本轮新上传资产，全量重置 `consumed = false`，将融合分析指令与历史产物摘要一并下发，在当前分支上创建融合节点。

4. 状态 D：DETACH_RESET（意图跳变 / 零历史断离）
   - 触发特征：用户指令开启完全独立的新任务，与当前活跃分支及所有历史分支的主题、产物与先验资产均无语义依赖；
   - 信封重构：触发自动断离（Auto-Detach）。彻底清空历史挂载，构造一个干净的“零历史净信封”。若本轮有新附件则仅挂载新附件。任务树中独立开启全新的并行分支。

5. 状态 E：SWITCH_BRANCH（切换回历史其他分支）
   - 触发特征：指令脱离了当前活跃任务分支的业务领域，转而依赖历史其它任务分支目录中某个非当前分支的主题上下文、沉淀产物或历史介质。目标分支集合严格受限于非活跃历史分支（在图结构上排除当前分支自环）；
   - 信封重构：任务树将焦点指针激活至目标历史分支，提取该目标分支沉淀的最终基底产物；若目标分支关联多模态物理介质且需要溯源，连带复位该分支原始资产，在目标分支末端追加新节点。

端侧 WebGPU 微模型推理引擎

- 运行时：通过 `@huggingface/transformers` (v3.8.1) 的 WebGPU / WASM 后端驱动；
- 选型模型：`onnx-community/SmolLM2-135M-Instruct-ONNX-GQA`（约 1.35 亿参数，量化后权重约 82MB，加载快，在移动端与笔记本核显上可流畅运行）；
- 兼容垫片：针对非标准环境（如较早 Chromium 移动端浏览器内核缺少原生 `Float16Array`），引入 `@petamoriken/float16` 垫片，防止张量解算 Crash。
- 针对 135M 微模型易发生的“系统提示词回吐泄漏”与“贪婪采样死循环”，本地运行引擎配置了严格的惩罚采样器：
  `do_sample: true`, `temperature: 0.6`, `top_p: 0.9`, `repetition_penalty: 1.25`, `max_new_tokens: 384`；
- 前端内置正则过滤器，实时抹除 `<|im_start|>`、`System:` 等泄露模板，保证视觉交付物的优雅纯净。



安全
1.引入 `DOMPurify 3.1.6` 净化管道，将所有模型流式输出、单节点产物及 Markdown 渲染严格封装于 `safeRenderMarkdown()`；
2.启发式扫描并剥离 `<script>`、`<iframe>`、`<object>`、`<form>` 标签及 `onerror`、`onload`、`onclick` 等内联 JavaScript 注入；
3. HTTP 响应注入 `X-Content-Type-Options: nosniff` 安全头，防止 MIME 嗅探劫持。
4.边缘内存滑动窗口令牌桶限流，采用温和自适应的内存令牌桶算法：
   - 桶容量：3（允许用户正常使用时的快速双击或连发 3 次）；
   - 补充速率：每 5 秒补充 1 个令牌（稳态等效持续约 12 请求/分钟）；
   - 存储介质：Worker Isolate 内存 Map，避免频繁写入 D1 。
5. 交互保护。超频时服务端返回 HTTP 429 与 `Retry-After: N` 响应；触发限流时，前端弹出自定义倒计时模态弹窗（Demo 环境保护提示），并自动将用户已发送的文本完整回填至输入框，倒计时结束后弹窗按钮自动转为“立即继续提问 ➔”并重新聚焦输入框。

商业化闭环
- 初始体验额度：新用户注册（邮箱验证码或 GitHub / Google OAuth）赠送 100 ⚡ 初始算力包；
- 双向邀请激励机制：老用户邀请新用户注册，老用户获赠 50 ⚡ 算力奖励，新用户获得初始 100 ⚡ + 邀请奖励 50 ⚡（共 150 ⚡）；
- 记账体系（D1 表 `credit_ledger`）：对每次扣费、注册赠予、卡密充值、网格共享收益记录流水账目，支持全量财务审计；
- 卡密兑换：管理员可在后台批量生成充值卡密（支持批次、额度、过期时间），用户一键兑换充值。
